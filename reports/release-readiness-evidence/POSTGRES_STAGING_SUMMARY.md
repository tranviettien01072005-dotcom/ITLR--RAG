## Root cause fixed and verified

A real valid PDF generated by installed Ghostscript was accepted by pdfinfo but the application's PDF worker failed with `UnknownErrorException: bad XRef entry`, resulting in HTTP 500. Installed old PDF.js expects Uint8Array slicing semantics; Buffer input caused this incompatibility. Only the worker's parser input conversion changed from `Buffer.from(workerData.buffer)` to `new Uint8Array(workerData.buffer)`. Worker isolation, resource/time limits, invalid-document classification, and upload validation remain in place.

Changed repository files only: `web/src/services/dataset-extract.ts` and `web/src/services/dataset-extract.test.ts`. The regression constructs a valid ASCII one-page PDF with correct xref offsets, then uses the real worker/parser. RED: one failed/three passed with `Document extraction failed`; GREEN: four passed. Typecheck, focused ESLint, build and scoped git diff whitespace check passed. After rebuilding and restarting Web, the real valid-PDF HTTP upload returned 200 pending, extracted the expected text, and downloaded byte-for-byte correctly. The supervising agent runs the combined full suite and owns documentation integration.

## Remaining limits

Search/chat/SSE upstream was an explicit HTTP fixture, not a neural API or LLM; these checks prove Web/DB lifecycle and browser protocol handling, not generation quality or model faithfulness. Moderation approval/catalog-export side effects, SMTP delivery/password-reset flow, all social/admin features, capacity/soak, Docker image/volume/network operation, production HTTPS/cookies, PITR, separate-host restore, role backup and disaster recovery were not tested here. Restoring into another database on the same temporary cluster is a bounded logical recovery drill. Local socket auth is trust inside a mode0700 socket directory; host-password behavior is specific to this isolated cluster.

For retained local fixtures, the cleanup script `cleanup_db_services.py` documents service shutdown, and no own server remains running. Restart PostgreSQL with extracted pg_ctl and `LD_LIBRARY_PATH=/tmp/itlr-release/pg-root/usr/lib/x86_64-linux-gnu`; reuse existing private settings without rerunning setup_db.cjs, which creates the new role/database once. Rerun harnesses only against the isolated fixture endpoints and expect additional fixture rows.
