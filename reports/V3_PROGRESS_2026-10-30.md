What this change does: adds a chunk retrieval path without removing the V2 artifact path. Hardens local index lifecycle and makes the previously conditional API tests run on temporary versioned artifacts. This continues the prior audit; it does not repeat a whole-repo audit.

Implemented:

- `itlr/core/chunks.py`: normalized per-chunk FAISS IndexFlatIP, existing BM25, reciprocal-rank fusion and optional CrossEncoder on at most 32 candidates. Validates vector shapes, finite values, nonzero norms, unique chunk identities and reranker output. Model errors propagate rather than being hidden.
- `build_embeddings_v2.py`: persists chunk vectors alongside the existing item means. `engine.py` loads the chunk index when this artifact exists. The chatbot semantic retrieval path uses actual matching chunks and their excerpts, rather than selecting a chunk after item retrieval. Old artifacts remain usable.
- Prompt evidence includes explicit chunk markers. Citation validation rejects chunk markers outside the selected evidence; existing item citation syntax remains supported. Identifier checks are not semantic entailment or a guarantee of faithfulness. Missing chunk markers are not yet a strict rejection condition.
- `locking.py` / `versioning.py`: Linux flock plus process-local thread serialization for activation, rollback and GC. Random suffix prevents same-second staging collisions. Rollback follows actual transitions; GC preserves current, previous and unfinished staging. Engine artifact loading holds a shared lifecycle lock against deletion while reading.
- CLI crawl/build writers serialize through the same pipeline lock. Concurrent refresh parent jobs have a separate refresh lock; children take the pipeline lock per write phase. Direct ad hoc writes and legacy scripts that do not participate in these locks are outside this guarantee.
- Engine reload constructs the replacement before publishing it. Failure preserves the previously loaded engine; readers can continue using the old reference while a reload constructs its candidate.
- Five API tests formerly gated by legacy artifact presence now use temporary versioned artifacts, a deterministic encoder fixture and synthetic CF data. Their endpoint assertions remain. Added chunk-loader integration test. No neural or real-user-data claim is attached to these fixtures.
- CI integration command now explicitly includes chunk, versioning and API integration tests. No new dependency, live API call, migration, activation or deployment.

TDD evidence:

- New chunk retrieval tests failed with missing implementation, then passed; actual FAISS is used with controlled vectors. CrossEncoder order is tested with a deterministic predictor, not a downloaded reranker.
- Wrong chunk citation was accepted before validation change and rejected afterward.
- Frozen clock staging collision and second rollback tests failed before changes and passed afterward.
- Unfinished staging was deleted by GC before the fix; regression now preserves it.
- Threaded and eight-process activation tests assert complete history and pointer consistency.
- Failed candidate reload test failed before the new reload interface and passes with old-engine retention.
- The API fixture initially exposed an empty TF-IDF vocabulary from common fixture terms; max_df=1.0 applies to this synthetic fixture only. Production thresholds were not weakened.

All chunks are candidates in this small experiment, unlike the bounded runtime pool. Query embeddings were measured once and shared between the two configurations. This is a single small, easy corpus experiment, not a significance test, load benchmark or proof of quality improvement. Faithfulness, hallucination and citation accuracy are null because generation was not run. There are no passage-level independent qrels yet.

Ponytail Ultra review:

What this change does: reuses existing primitives and preserves old artifacts. Scope assumes a local Linux filesystem, one API process and cooperating CLI writers.

Must fix before release:

1. V3 is not end-to-end release complete. API search and the early off-topic gate still use the V2 item path; existing intent handlers can return knowledge/template answers. Fix by integrating and evaluating these paths before declaring all requests chunk-grounded. Otherwise product behavior differs by intent and endpoint. This is an explained release blocker, not claimed resolved.
2. Concurrency checks cover normal execution, not crash recovery. Pointer and history are separate atomic file replacements, not one durable transaction; power failure between them can lose a history transition. Network filesystem locks and multiple hosts are unverified. Add crash-injection tests/durable state before promising crash-safe lifecycle operation.
3. CrossEncoder integration is tested with a mock predictor only. Model cache availability, real passage reranker quality and CPU/RAM cost remain unverified. No production latency claim is made.
