# ITLR–RAG | Intelligent IT Learning Platform

## V3 chunk retrieval and lifecycle checkpoint

Historical record: 2026-10-30. This document describes evidence and decisions at that checkpoint. See the [current platform guide](../README.md) and [current validation](VALIDATION.md) for later changes and runtime status.

This checkpoint added chunk retrieval alongside the V2 artifact path, hardened the local index lifecycle and replaced artifact-conditional API tests with temporary versioned fixtures. It continued the previous audit without restarting a repository-wide review. Later integration and durability work is documented in [V3_RESTRUCTURING_2026-10-30.md](V3_RESTRUCTURING_2026-10-30.md).

### Implementation and compatibility

- `itlr/core/chunks.py` uses normalized per-chunk FAISS IndexFlatIP, existing BM25, reciprocal-rank fusion and optional CrossEncoder over at most 32 candidates. It validates vector shape, finite values, nonzero norms, unique identities and reranker output; model errors propagate.
- `build_embeddings_v2.py` persists chunk vectors alongside item means. `engine.py` loads the chunk index when present, and semantic chatbot retrieval selects matching chunks/excerpts directly. Legacy artifacts remain supported.
- Prompt evidence carries chunk markers. Validation rejects markers outside selected evidence while retaining item citation syntax. At this checkpoint, missing chunk markers were not strictly rejected. Identifier checks do not establish semantic entailment or faithfulness.
- `locking.py`/`versioning.py` combine Linux flock and process-local thread serialization for activation, rollback and GC. Random staging suffixes prevent same-second collisions. Rollback follows transitions; GC preserves current, previous and unfinished staging. Engine loads hold a shared lifecycle lock against concurrent deletion.
- CLI crawl/build writers share a pipeline lock. Concurrent refresh parents use a separate refresh lock; children acquire the pipeline lock for each write phase. Ad hoc writers and legacy scripts outside these locks are excluded from the guarantee.
- Reload constructs a complete replacement before publication. Failure retains the old engine; readers can continue using its reference during construction.
- Five formerly conditional API tests use temporary versioned artifacts, a deterministic encoder and synthetic CF; endpoint assertions remain. A chunk-loader integration test was added. CI explicitly includes chunk, versioning and API integration tests. No dependency, live API call, database migration, active index rebuild/activation or deployment was added.

### Regression evidence

Chunk tests first failed for missing implementation, then passed using real FAISS with controlled vectors. A deterministic predictor tested CrossEncoder ordering without downloading a real reranker. Wrong chunk citations were accepted before validation and rejected afterward. Frozen-clock staging collisions and second rollback tests reproduced failures before corrections. GC previously deleted unfinished staging; the regression now verifies preservation. Threaded and eight-process activation tests assert complete history/pointer consistency. Candidate reload failure now preserves the previous engine.

The API fixture initially produced an empty TF-IDF vocabulary from common fixture terms; `max_df=1.0` is limited to that synthetic fixture. Runtime thresholds and endpoint assertions were preserved.

### Real embedding experiment

Entry point: `eval/bench_chunks_v3.py`; raw output: `reports/chunks_v3_experiment.json`.

| Configuration | Recall@5 | MRR@5 | nDCG@5 | p95 query + retrieval |
|---|---:|---:|---:|---:|
| Item mean dense | 1.0 | 1.0 | 1.0 | 117.41 ms |
| Chunk BM25 + dense + RRF | 1.0 | 1.0 | 1.0 | 118.36 ms |

The run used E5-base CPU, eight checked-in real documentation snapshots, 98 chunks and eight hand-authored item-level qrels, without reranking. Query embeddings were measured once and shared. Every chunk was eligible, unlike the bounded runtime pool. This small, easy experiment is neither a significance/load test nor evidence of improved quality/speed. Independent passage qrels were absent. Generation was excluded, so faithfulness, hallucination and citation accuracy are null.

### Review and unresolved gates

Ponytail Ultra review assumed local Linux storage, one API process and cooperating CLI writers. It found no additional unexplained High/Critical issue after staging preservation and failed-reload continuity fixes. Existing primitives/legacy artifacts were retained without extra dependency layers or refactor-only changes.

Three release blockers remained:

1. API search and the early off-topic gate still used V2 item retrieval, while intent handlers could produce knowledge/template answers. V3 therefore did not ground all endpoints/intents in chunks.
2. Pointer and history used separate atomic replacements. Normal-execution concurrency tests did not cover a crash between them, which could lose a history transition. Durable state/crash injection, network-filesystem and multihost behavior needed further validation.
3. CrossEncoder tests used a mock predictor. Real model cache, passage quality and CPU/RAM cost remained unverified.

No paid DeepSeek call was authorized. PostgreSQL migrations/transactions, Docker execution (`docker`/`psql` absent from PATH), browser E2E, new full V3 build/activation, full-corpus retrieval, semantic faithfulness/hallucination, crash recovery and multihost deployment were outside the checks. Existing DeepSeek mock regressions ran; failover was unchanged. Active runtime artifacts were not upgraded.

Final checks: full Python suite 245 passed / 0 skipped in 44.60s, outside the sandbox with OMP/MKL/OpenBLAS threads=1, `USE_OLLAMA=0`, `DISABLE_RERANKER=1`. Web remained 59 passed with 25.01% line coverage. compileall and `git diff --check` passed; the four prior audit fixes remained covered.
