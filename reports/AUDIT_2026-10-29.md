# ITLR–RAG | Intelligent IT Learning Platform

## Collection and retrieval correctness audit

Historical record: 2026-10-29. This document describes evidence and decisions at that checkpoint. See the [current platform guide](../README.md) and [current validation](VALIDATION.md) for later changes and runtime status.

The audit covers collection reconciliation, source policy, V2 evaluation and activation probes. It assumes one API worker and sequential refresh jobs. It is a scoped review, with Ponytail Ultra applied before corrections and after the diff. No paid provider call, database migration, index activation, data deletion or deployment occurred.

### Correctness findings and resolutions

| Finding | Reproduction | Correction and limit |
|---|---|---|
| Rolling feeds incorrectly remove archived resources (`itlr/collect/runner.py`) | A valid archived article absent from a recent feed became `missing=1`. DEV uses `per_page=30`; RSS/news listings are incomplete inventories. | Missing detection requires explicit `listing_is_complete: true`; default false. Seen URLs restore missing records even beyond the fetch budget. Complete-inventory tests retain deletion/restoration assertions. Previously missing URLs absent from current feeds need separate review before restoration. |
| String configuration grants full-text permission (`itlr/collect/sources.py`) | `bool("false")` grants permission; six string/integer/null policy cases reproduced the error. | Require JSON booleans for full-text and inventory-completeness policies. Defaults remain false; malformed configuration raises `SourcesError`. |
| V2 nDCG has a nonstandard discount (`eval/eval_v2_real.py`) | Ranks `[2,1]`, grades `{1:3,2:1}` yielded 0.739130 instead of 0.709810; full precision 0.7391304348 versus 0.7098097414. | Reuse `itlr.eval.metrics.ndcg_at_k` with complete relevance inventory for the ideal ranking. Historical V2 results were not recalculated. |
| Small catalogs fail activation probes (`itlr/indexv2.py`) | Two documents with `top_k=5` raised numpy `argpartition` ValueError. | Cap candidates at catalog size; reject nonpositive limits and empty inputs. Corrected fixture self-recall is 1.0. |

All four defects have failing pre-fix and passing post-fix regressions. The grouped pre-fix run had eight failures: six policy cases, rolling-feed retention and nDCG. The small-catalog probe failed in a separate run. These examples establish fixture correctness, not real-query quality gains.

### Architectural gaps at this checkpoint

V2 encoded chunks then averaged them into item vectors (`itlr/pipelines/build_embeddings_v2.py`); chunk metadata existed without searchable chunk vectors. Passage dilution was a design concern, with no measured retrieval regression. The proposed V3 needed persisted chunk vectors/ownership, shared evidence selection, stable item response contracts and independently labeled passage evaluation before activation.

Version IDs had second precision, and `itlr/versioning.py` history updates used read/modify/write without visible locking. Concurrent refreshes could share staging and lose transitions. Only one refresh job was permitted pending serialization and concurrent-invocation tests. See the later [V3 checkpoint](V3_PROGRESS_2026-10-30.md) and [shared-retrieval record](V3_RESTRUCTURING_2026-10-30.md) for subsequent work.
